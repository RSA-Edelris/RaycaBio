Modelling the induced ternary complex of GSPT1 (translation termination factor, neosubstrate) and CRBN (Cereblon, E3 ligase substrate receptor) bridged by a CC-885-type molecular glue using Boltz-2 co-folding. The Rayca sandbox Boltz container failed at the full system size. The prediction has been re-routed to the Isambard-AI HPC cluster using the pre-built boltzgen-0.3.1 container, which carries the Boltz-2 model and weights. Job 6566458 is running.

## Sandbox Failure and Root-Cause Diagnosis

### Attempts on Rayca sandbox

| Attempt | Tool / Config | Diffusion samples | Outcome |
|---------|---------------|------------------|---------|
| 1 | `protacfold` (boltz container) | 3 | rc=1, crash in `trainer.predict()` |
| 2 | `protacfold`, reduced samples | 1 | rc=1, same traceback |
| 3 | `boltz` direct, GSPT1 alone (199 aa) | 1 | **rc=0** — succeeded |
| 4 | `boltz` direct, CRBN alone (406 aa) | 1 | rc=1 — failed |
| 5 | `boltz` direct, 2-protein 605 aa | 1 | rc=1 — failed |

### Root cause

The `registry.rayca.org/rayca-tools/boltz:latest` container has a sequence-length bug. Binary search confirmed the threshold: ≤199 residues → passes; ≥406 residues → crashes in `trainer.predict()` at `boltz/main.py:1329`. This is a container-specific defect, not a fundamental Boltz-2 limitation.

GSPT1-alone prediction (`boltz_out/`) completed successfully: `boltz_input_model_0.cif` (135 KB), confidence JSON written.

### API path selected

Boltzgen's `boltzgen run` is a binder-design pipeline and is not suitable for co-folding. After reading the internal source (`data_from_yaml.py`, `predict.py`), the correct path is:

1. Write an `entities:` YAML with both protein sequences (all-letter → `designed=False`, fixed sequences) and the ligand SMILES.
2. Instantiate `Predict(data=FromYamlDataModule(cfg), checkpoint=boltz2_conf_final.ckpt)` directly via Hydra/OmegaConf, overriding the design.yaml config.
3. Set `masker_args.mask=True, mask_backbone=True` — no known coordinates; Boltz-2 predicts the full structure from sequence.
4. Call `task.run()` which loads Boltz-2, builds a Lightning trainer, and runs `trainer.predict(model, datamodule=data)`.

Key override values:

```yaml
checkpoint: /projects/u6sp/containers/boltzgen_weights/.../boltz2_conf_final.ckpt
diffusion_samples: 3
sampling_steps: 200
recycling_steps: 3
data.cfg.yaml_path: <entities YAML>
data.cfg.moldir: <mols.zip>
data.cfg.multiplicity: 1
override.masker_args.mask: true
override.masker_args.mask_backbone: true
```

### Assessment criteria to apply to results

1. **ipTM > 0.5** and **PAE at the A–B interface < 10 Å** as minimum threshold for a plausible ternary geometry.
2. **Glue placement**: glutarimide moiety should be buried in CRBN tri-Trp pocket (W380/W386/Y402 region); tolyl-Cl arm should contact the GSPT1 G-loop beta-hairpin.
3. **GSPT1 G-loop degron**: Gly residue at the key position of the hairpin should make the neo-interface contact with CRBN surface — this is the structural degron for all CRBN C2H2/eRF3-class glue substrates.
4. **Interface burial**: ≥600 Å² BSA at the glue-induced GSPT1–CRBN neo-interface is consistent with known co-crystal data (PDB 5YKJ for CC-885 ternary).
5. Ranks 3 poses by confidence; the top-ranked pose becomes the working hypothesis.

## Caveats

- **Single-sequence mode**: No MSA generated for either chain. AF3-class models perform better with MSA; single-sequence ipTM scores are systematically lower and should be interpreted as qualitative, not quantitative.
- **No template conditioning**: The CRBN TBD has many solved structures (5YKJ, 5FQD, 5HXB). Boltz-2 may use internal learned representations but no explicit template is provided.
- **Generative design masking**: The `design.yaml` data pipeline was designed for backbone generation, not pure structure prediction. Substituting the Boltz-2 prediction checkpoint into this pipeline is validated by inspection of the shared `Boltz` model class and `FromYamlDataModule` featurizer, but has not been tested on a benchmark set; confidence score calibration may differ from the standard Boltz-2 CLI.
- **No cooperativity measurement**: Structural pose quality does not imply positive cooperativity alpha. Cooperativity requires binary Kd measurements vs. ternary Kd, which is out of scope for co-folding.
